# Telegram Bot Host — Koyeb Service واحدة

هذا هو الـ Host الرئيسي الذي يرفع إليه المستخدمون ملفات بوتات Telegram من داخل البوت. لا يحتاج إلى Service مستقلة لكل بوت.

## كيف يعمل

عند رفع ملف `.py` أو `.js` يفحص الـ Host syntax أولاً، ولا يسجل الملف إذا كان فيه خطأ. ملفات ZIP يتم فحصها كذلك ضد التلف ومسارات الخروج من مجلد المستخدم. بعد ذلك يعمل زر `Run` مباشرة. عند رفع ZIP ثم اختيار `Extract ZIP`، يفك الـ Host الأرشيف بشكل آمن ويسجل ملفات Python وJavaScript الموجودة داخله. عند التشغيل:

1. يبحث عن `requirements.txt` بجانب ملف التشغيل أو في مجلد المستخدم.
2. ينشئ `.venv` خاصة بذلك البوت.
3. يثبت المتطلبات داخل تلك البيئة فقط، بما فيها `aiogram` إذا استعمله البوت.
4. يختار `main.py` أو `bot.py` أو `app.py` أو `run.py` أو `index.py` تلقائياً. وإذا كان هناك ملف واحد فقط من نوع Python يستعمله.
5. يشغل البوت في process منفصل ويحفظ السجل في ملف مستقل.
6. ينتظر ثانيتين افتراضياً ويتأكد أن العملية لم تتوقف مباشرة. إذا فشل البوت تظهر رسالة الخطأ من السجل بدل إعلان التشغيل ناجحاً.

إذا تغيّر محتوى `requirements.txt` يعاد بناء البيئة الافتراضية تلقائياً. إذا لم يوجد `requirements.txt` يستعمل Python الخاص بالـ Host.

## إعداد Koyeb

أنشئ **Service واحدة فقط** من هذا المجلد، واختر Dockerfile:

مهم: شغّل **نسخة واحدة فقط** من الـ Host وبنفس `BOT_TOKEN`. أوقف أي نسخة قديمة على Koyeb وأي تشغيل محلي أو Worker آخر يستعمل نفس التوكن، وإلا يظهر `TelegramConflictError` لأن Telegram يسمح بطلب polling واحد فقط.

```text
Port: 8080
Protocol: HTTP
Health check path: /health
```

أضف متغيرات البيئة التالية:

```text
BOT_TOKEN=توكن Host الرئيسي الجديد
OWNER_ID=رقم حساب المالك
ADMIN_ID=رقم حساب الأدمن
YOUR_USERNAME=@username
FORCE_CHANNEL=@channel
UPDATE_CHANNEL=https://t.me/channel
MAX_UPLOAD_BYTES=52428800
MAX_ARCHIVE_FILES=100
MAX_ARCHIVE_BYTES=209715200
STARTUP_CHECK_SECONDS=2
```

لا ترفع ملف `.env` إلى GitHub أو إلى Docker. ضع المتغيرات من إعدادات Koyeb.

## صيغة رفع بوت

يفضل أن يكون كل بوت في ZIP خاص به:

```text
mybot.zip
├── main.py
├── requirements.txt
└── ملفات البوت الأخرى
```

أو:

```text
mybot.zip
└── mybot/
    ├── bot.py
    ├── requirements.txt
    └── config.py
```

لا تضع أسراراً داخل ZIP. بوت Telegram يجب أن يقرأ التوكن هكذا:

```python
import os
TOKEN = os.environ["BOT_TOKEN"]
```

## حدود النسخة المجانية

الخدمة الواحدة تجمع Host وجميع البوتات، لذلك الذاكرة والمعالج مشتركان. لا تشغل عدداً كبيراً من البوتات الثقيلة. تثبيت أول requirements قد يستغرق عدة دقائق، والتثبيت يحدث عند الضغط على `Run` وليس عند كل تشغيل لاحق.

Koyeb filesystem محلي وغير مضمون كـ Storage دائم بعد إعادة البناء. قواعد البيانات وملفات البوتات قد تحتاج Storage خارجياً إذا كانت مهمة.

## تنبيه أمان

هذا النظام يشغل كوداً يرفعه المستخدم داخل نفس الحاوية. هو مناسب للاستعمال الشخصي أو لمستخدمين موثوقين، وليس منصة عامة لمستخدمين مجهولين. لا تفتح صلاحية الرفع للناس كلهم دون sandbox حقيقي منفصل لكل بوت.
